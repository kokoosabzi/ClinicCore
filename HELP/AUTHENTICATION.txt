# راهنمای احراز هویت و مدیر اولیه

## ایجاد مدیر در نصب تازه

در اجرای `setup.bat`، اگر `.env` وجود نداشته باشد، اسکریپت bootstrap:
- یک `SECRET_KEY` تصادفی و طولانی تولید می‌کند.
- یک رمز تصادفی برای مدیر اولیه تولید می‌کند.
- مقادیر را در `.env` محلی ذخیره می‌کند.
- رمز اولیه را فقط در خروجی همان اجرا نمایش می‌دهد.

نام کاربری پیش‌فرض `admin` است. رمز اولیه را امن نگهداری کنید و در اولین ورود تغییر دهید.

## رفتار حساب مدیر

اسکریپت `scripts/seed_admin.py` حساب مدیر را با password hash ایجاد می‌کند و `must_change_password=True` را تنظیم می‌کند. اگر کاربر از قبل وجود داشته باشد، رمز و حساب موجود را بازنویسی نمی‌کند.

## نقش‌های فعلی

مدل فعلی شامل نقش‌های زیر است:
- admin
- doctor
- secretary
- accountant

وجود نقش‌ها به معنی پیاده‌سازی مجوزهای ریزدانه برای تمام عملیات نیست. تکمیل پنل مدیریت کاربران و ماتریس مجوزها باید در یک Sprint مستقل انجام شود.

## نشست و امنیت

- رمز عبور به‌صورت hash ذخیره می‌شود.
- صفحات و عملیات محافظت‌شده به احراز هویت و کنترل نقش متکی هستند.
- فرم‌های حساس باید CSRF token را حفظ کنند.
- برای اجرای شبکه‌ای یا دسترسی خارج از همین رایانه، HTTPS و تنظیمات امن نشست باید جداگانه پیکربندی و ارزیابی شوند.

## تغییر رمز

کاربر مدیر می‌تواند رمز را پس از ورود از مسیر تغییر رمز اجباری اولیه عوض کند. ابزار خط فرمان موجود:
```powershell
.\.venv\Scripts\Activate.ps1
python scripts/change_admin_password.py
```

هرگز رمز واقعی یا فایل `.env` را در مخزن Git قرار ندهید.
